# คู่มือขึ้นเว็บใช้งานจริง — ไม่ต้องเขียนโค้ดเพิ่ม

ระบบถูกแปลงให้พร้อมใช้งานจริงแล้ว ใช้ **Supabase** (ฐานข้อมูล + ที่เก็บรูปภาพ, ฟรี) และ **Vercel** (โฮสต์เว็บไซต์, ฟรี, ได้โดเมนของตัวเอง) ทำตามขั้นตอนด้านล่างได้เลย ใช้เวลาประมาณ 30-60 นาที ไม่ต้องเขียนโค้ดเพิ่มแม้แต่บรรทัดเดียว

---

## ขั้นตอนที่ 1: สร้างฐานข้อมูลบน Supabase

1. ไปที่ https://supabase.com แล้วสมัครสมาชิก (ใช้ GitHub หรืออีเมลก็ได้) — ฟรี
2. กด **New project** ตั้งชื่อโปรเจกต์ เช่น `it-asset-north` เลือก region ใกล้ไทยที่สุด (Singapore) ตั้งรหัสผ่านฐานข้อมูลแล้วจดไว้
3. รอสักครู่จนโปรเจกต์สร้างเสร็จ (~2 นาที)
4. ไปที่เมนู **SQL Editor** ทางซ้าย → กด **New query**
5. เปิดไฟล์ `supabase-schema.sql` ที่แนบมาให้ → copy ทั้งหมด → วางในช่อง SQL Editor → กด **Run**
   - ขั้นตอนนี้จะสร้างตาราง `branches`, `assets`, `tickets`, `ticket_photos` ให้อัตโนมัติ
6. ไปที่เมนู **Storage** ทางซ้าย → กด **New bucket**
   - ตั้งชื่อ bucket ว่า `ticket-photos` (ต้องสะกดตรงนี้ให้ตรง)
   - เปิด toggle **Public bucket** เป็น ON (เพื่อให้รูปโหลดขึ้นเว็บได้)
   - กด **Create bucket**

## ขั้นตอนที่ 2: ดึงค่า API Key

1. ไปที่เมนู **Project Settings** (รูปเฟือง) → **API**
2. คัดลอกค่า 2 ค่านี้เก็บไว้:
   - **Project URL** (หน้าตาแบบ `https://xxxxxxxxxxxx.supabase.co`)
   - **anon public key** (คีย์ยาวๆ ใต้หัวข้อ Project API keys)

## ขั้นตอนที่ 3: อัปโหลดโค้ดขึ้น GitHub

1. ไปที่ https://github.com สมัครสมาชิกฟรี (ถ้ายังไม่มี)
2. กด **New repository** ตั้งชื่อ เช่น `it-asset-management` เลือก Private หรือ Public ก็ได้ → กด **Create repository**
3. ในหน้า repository ที่สร้างเสร็จ กด **uploading an existing file**
4. ลากไฟล์/โฟลเดอร์ทั้งหมดที่แนบมาให้ (ทั้งโปรเจกต์ `asset-app`) ลงไปวาง แล้วกด **Commit changes**
   - **ข้อควรระวัง:** อย่าอัปโหลดไฟล์ `.env` (ถ้ามี) ขึ้น GitHub เพราะมีข้อมูลลับ — ใช้ `.env.example` เป็นตัวอย่างเฉยๆ

## ขั้นตอนที่ 4: Deploy บน Vercel

1. ไปที่ https://vercel.com สมัครสมาชิกโดยเลือก **Continue with GitHub** (ให้เชื่อมบัญชี GitHub ที่เพิ่งใช้)
2. กด **Add New… → Project**
3. เลือก repository `it-asset-management` ที่เพิ่งอัปโหลด → กด **Import**
4. ก่อนกด Deploy ให้เปิดส่วน **Environment Variables** แล้วเพิ่ม 2 ค่า:
   | Name | Value |
   |---|---|
   | `VITE_SUPABASE_URL` | (Project URL จากขั้นตอนที่ 2) |
   | `VITE_SUPABASE_ANON_KEY` | (anon public key จากขั้นตอนที่ 2) |
5. กด **Deploy** รอประมาณ 1-2 นาที
6. เสร็จแล้ว Vercel จะให้ลิงก์เว็บไซต์มาทันที เช่น `it-asset-management.vercel.app` — เปิดลิงก์นี้ใช้งานได้จริงเลย

## ขั้นตอนที่ 5 (ไม่บังคับ): ผูกโดเมนของตัวเอง

ถ้าองค์กรมีโดเมนอยู่แล้ว (เช่น `it.บริษัทของคุณ.co.th`):
1. ในโปรเจกต์ Vercel → ไปที่ **Settings → Domains**
2. พิมพ์โดเมนที่ต้องการ → Vercel จะให้ค่า DNS record มา
3. เอาค่านั้นไปตั้งที่ผู้ให้บริการโดเมน (เช่น GoDaddy, Cloudflare, หรือ IT ขององค์กรที่ดูแล DNS)
4. รอ DNS อัปเดต (มักไม่เกิน 1 ชั่วโมง) ก็ใช้โดเมนตัวเองได้

## ข้อควรรู้ก่อนใช้งานจริง

- **ยังไม่มีระบบ login** — ทุกคนที่มีลิงก์เข้าถึงและแก้ไขข้อมูลได้หมด เหมาะกับใช้งานภายในทีมที่ไว้ใจกัน ถ้าต้องการจำกัดสิทธิ์ ให้แจ้งมาเพิ่มได้ภายหลัง (Supabase มีระบบ Auth ในตัว เพิ่มได้โดยไม่ต้องเปลี่ยน backend)
- **แผนฟรีของ Supabase**: database 500MB, storage 1GB, พอสำหรับเริ่มต้นใช้งานจริงหลายร้อยรายการ ถ้าข้อมูล/รูปภาพเยอะขึ้นมากในอนาคต ค่อยอัปเกรดแผนเสียเงิน (เริ่มต้น ~$25/เดือน)
- **แผนฟรีของ Vercel**: เพียงพอสำหรับการใช้งานภายในองค์กรทั่วไป
- ทุกครั้งที่แก้โค้ดแล้วอัปขึ้น GitHub ใหม่ Vercel จะ deploy เวอร์ชันใหม่ให้อัตโนมัติ

## ถ้าเปิดเว็บแล้วขึ้น error "เชื่อมต่อฐานข้อมูลไม่สำเร็จ"
มักเกิดจาก:
1. ใส่ `VITE_SUPABASE_URL` หรือ `VITE_SUPABASE_ANON_KEY` ผิด/ไม่ครบ → ไปแก้ที่ Vercel → Settings → Environment Variables แล้วกด Redeploy
2. ยังไม่ได้รัน `supabase-schema.sql` → กลับไปทำขั้นตอนที่ 1 ข้อ 5
3. ยังไม่ได้สร้าง bucket ชื่อ `ticket-photos` → กลับไปทำขั้นตอนที่ 1 ข้อ 6
